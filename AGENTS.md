# Agent Instructions

This repository is intentionally scoped around pairing and validation first, then live worker session management, explicit one-shot relay paths, live ChatGPT readiness, opt-in live ChatGPT read/send, deterministic supervision, and bounded safe recovery, followed by concurrent multi-pair runtime orchestration.

- Keep M5b limited to one-shot live ChatGPT read/send.
- Keep M7 limited to deterministic observation, classification, safe one-shot relay orchestration through the M6 ledger, and pause/resume control.
- Keep M8 limited to bounded, deterministic, opt-in recovery: transport reconnects, session verification, bounded backoff, and verify-only `STUCK` handling. Recovery must never use AI/model judgment, must never autonomously re-prompt a stuck agent or send corrective prompts, and must never auto-resume an ambiguous interrupted relay (`DELIVERING` records block with `RELAY_AMBIGUOUS` until reconciled).
- Keep M9 limited to concurrent multi-pair runtime orchestration with strict isolation: per-pair async supervisor loops, per-pair persistence and event correlation, hard duplicate-identity rejection at startup, and narrow FIFO browser locking. One pair's failure or backoff must never stall or terminate the others.
- Keep M10a limited to an Electron desktop shell/dashboard that reuses core APIs only. Never duplicate core runtime/validator/persistence logic in the renderer or main. The renderer must never access SQLite, OpenCode/CDP, or the filesystem directly, and IPC must be a narrow typed `contextBridge` over an explicit whitelisted `desktop:*` channel set with no generic execute/read/write/arbitrary channel. Keep the renderer sandboxed (`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`). Do not present a working "Launch Browser" button for a bundled or embedded engine: product browsers attach to an external Chrome/Chromium over CDP only (see the launcher rule below). Sensitive values (passwords, cookies, tokens) must never cross to the renderer. Closing the app stops runtimes started by this desktop process but never kills an external OpenCode server or external Chrome. Build output goes to `desktop-dist/` (gitignored).
- Do not add watchers, supervisor loops, dashboards, or autonomous recovery daemons beyond the corresponding milestone's scope. Recovery runs only under `supervise --watch`, `runtime start`, or the explicit `recovery retry` command.
- Only send live messages to ChatGPT through explicit one-shot commands with live ChatGPT enabled or configured.
- Only send live messages to OpenCode through explicit one-shot commands.
- Do not use AI/model judgment for readiness or state decisions. State classification must be deterministic.
- Keep ChatGPT deterministic and mocked by default.
- Preserve the worker/planner-neutral architecture. Avoid names that imply this repo only supports OpenCode and ChatGPT.
- Keep runtime state in `data/` and operational logs in `logs/`; both directories are gitignored except for `.gitkeep`. Persist against the local SQLite store under `src/persistence` (Node built-in `node:sqlite`), never commit the DB file.
- Prefer small modules under `src/sessions`, `src/validator`, `src/relay`, `src/persistence`, `src/supervisor`, `src/recovery`, and `src/adapters`. Shared DTOs belong in `src/contracts`, and layer-neutral helpers (async primitives, URL/canonicalization helpers, readiness constructors) belong in `src/util`: adapters are the lowest layer and must never import upward into `src/runtime`, `src/validator`, `src/relay`, `src/application`, or `desktop/`, and core must never import from `desktop/`.
- Project pairs (`src/application/project-pair-service.ts`, `src/sessions/project-pairs.ts`, `config/projects.local.json`) are a separate, coarser worker-project ↔ planner-project identity layer. Keep them read/write through their repository, keep ids stable and ownership unique, and use the neutral `worker` / `planner` keys (legacy `opencode` / `chatgpt` keys are accepted on read only).
- `src/remote/remote-server.ts` is an optional, explicitly wired HTTP control API. It may be started only by the explicit headless service entrypoint (`agent-relay service start` / `npm run relay -- service start`). It must never be started implicitly by ordinary CLI commands (other than `service start`), the Electron desktop startup, supervisors, watchers, or autonomous recovery daemons. It requires a bearer token (`RELAY_REMOTE_TOKEN`; refuse to start without one), compares tokens in constant time, defaults to a loopback bind (non-loopback requires explicit opt-in), caps request bodies, and must never reflect internal error messages or request paths to callers.
- The desktop shell may start a dedicated local Chrome/Chromium profile with a loopback CDP port and **attach over CDP only**; it never bundles or drives a managed browser engine. Any launcher-supplied endpoint is validated as loopback http(s), and `opencode serve` started by this app must be given a password (`OPENCODE_SERVER_PASSWORD` / `AGENT_RELAY_OPENCODE_PASSWORD`) rather than started unsecured.
